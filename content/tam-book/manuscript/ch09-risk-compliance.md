# 第 9 章　风险与合规

> 前面几章解决"把服务做好"，本章解决"别让事情变糟，变糟了兜得住"。技术纵深让你看见系统的短板，业务洞察让你知道出事的代价，关系经营让你有人可报——风险与合规是把这三者变成一套前置动作的能力：在事故发生前看见它，在监管到来前备好它。

## 9.1 能力定义

> **风险与合规，是把"可能出事"和"不许出事"分开管理的能力：风险用概率与影响去权衡，合规用底线与证据去遵守。**

先分清两个半区，它们的管理逻辑完全不同：

- **风险**是概率题：可能发生的坏事。可以评估、可以接受、可以转移、可以缓解——承认风险存在并明示权衡，是专业；
- **合规**是判断题：规则画出的底线。没有"接受违规"这个选项，只有"遵守"和"代价"——合规问题的答案在事前，不在事后。

混淆两者的代价都很贵：把风险当合规管，团队草木皆兵、什么都不敢做；把合规当风险管，"权衡一下先上线"，金融场景里这一念就是监管事件的起点。

TAM 的定位要说清：你不是风险部门，也不是合规官。你是**客户现场的风险传感器**和**合规的第一公里**——看得见最早的信号，守得住最近的边界，传得到该知道的人。

## 9.2 风险登记册：风险的中央账本

风险登记册（Risk Register）是所有风险的唯一事实源。模板见工具箱（模板 09），核心要素：

| 要素 | 说明 |
| --- | --- |
| 风险描述 | 一句话说清"什么条件下会发生什么坏事"，忌写"系统可能有风险"这种正确的废话 |
| 类别 | 技术 / 业务 / 组织 / 合规 |
| 概率 × 影响 | 各分三档即可（高/中/低），乘出等级；粒度太细的评分表是分析瘫痪的温床 |
| Owner | 每条风险一个具名负责人——写"双方共同关注"等于没人负责 |
| 缓解动作与期限 | 没有动作的"风险"只是焦虑，不入册 |
| 复审日期 | 风险会变质：概率在变，影响在变，客户在变 |

三条纪律：

1. **重大风险双方会签**：让客户书面知晓，不是为了让客户背锅，而是让客户参与决策——风险被客户会签接受，和被客户事后发现，是两种完全不同的信任事件（第 7 章）；
2. **月度过册**：登记册是月度服务回顾（8.5）的固定议程，不过册的登记册三个月就变成考古现场；
3. **来源多元化**：架构评审结论（第 5 章）、SLA–OLA 审计答不上来的条目（8.3）、健康检查、重保体检（第 18 章）、客户组织异动，全部汇入同一本册。

## 9.3 主动式风险扫描

登记册回答"已知风险管得怎样"，扫描回答"未知风险在哪"。三道扫描线：

**技术扫描**：容量水位与增长曲线、版本生命周期（EOS/EOL 逼近的组件，通告来源见附录 F）、单点与隐性依赖、配置漂移（8.4）。这条线自动化程度最高。

**业务扫描**：把客户的业务日历（6.2.2）当作战地图扫——决算、大促、监管报送窗口前，冻结纪律、容量余量、值守排班是否就绪。业务窗口是放大器：同样的故障，发生在决算日和普通周二，是两个级别的事故。

**组织扫描**：最容易漏的一条。客户关键人变动、预算收缩、决策链重组、你方团队的人员流失——第 7 章关键人地图的任何异动都是风险信号。核心系统换帅三个月内，是既往承诺失效的高发期。

**节奏建议**：每周快扫（自动化告警 + 30 分钟人工过一遍）、每月深扫（结合服务回顾）、每季全面体检（与 QBR 联动，输出入册）。

**AI 杠杆**：异常检测、容量趋势外推、变更文本与通告聚合，AI 都比人快（第 22、23 章）。但"这个信号算不算风险、值几级"的判断在人——AI 负责让信号浮上来，人负责给信号定性质。

## 9.4 审计与监管配合

金融客户的审计与监管检查是常态事件，不是意外事件。TAM 在其中的角色：**证据的提供者，口径的把关人**。

三项纪律：

1. **如实**：不修饰、不隐瞒、不替客户"美化"材料。帮客户在审计材料里注水，一旦穿帮，你和公司在监管那里的信用一次性清零；
2. **留痕在平时**：值班日志、变更台账、演练记录、复盘报告（附录 I、K 与问题复盘标准）——证据链是日常治理的副产品。审计前突击补材料的，补出来的材料本身就会成为问题；
3. **口径一致**：对外输出的每一个数字、每一个结论，与内部事实一致，且只由授权接口输出。监管问询中"随口一说"的代价，第 19 章（监管事件上报口径）会展开。

行业特殊性（等保 2.0、数据分级分类、监管报送）放在第 16 章；本章只立通用纪律。

## 9.5 数据安全边界

TAM 手里有客户环境的拓扑、配置、日志、甚至业务数据——这是信任的实物形态，也是事故的实物形态。三条铁律（与附录 B 运营规范 B.3.6/B.3.7 一致）：

1. **数据不出授权边界**：客户数据只在客户授权的环境、期限、用途内使用；带离即违规，不论动机；
2. **进 AI 工具前先问能不能进**：工单内容、日志片段、架构图——喂给公网模型前先过一遍数据分级。AI 提效的诱惑越大，这条越要靠纪律而不是自觉（第 24 章展开）；
3. **脱敏是可验证动作**：案例、复盘、培训材料的脱敏要有检查清单（客户名、域名、IP、账号、业务数字特征），"已经脱敏了"这句话本身不算脱敏。

边界被违反时的处理顺序：立即停止扩散 → 上报 → 复盘定责。记住：**隐瞒比违反本身严重得多**——违反是事故，隐瞒是诚信事件，前者可修复，后者击穿信任账户底层（第 7 章）。

## 9.6 分级标准

| 级别 | 判定标准（可观察行为） |
| --- | --- |
| L1 有账 | 风险登记册存在且在更新，每条有 Owner 和复审日期 |
| L2 会扫 | 三道扫描线有节奏地跑，新风险持续入册 |
| L3 前置 | 多数风险在酿成事件前被缓解动作关闭；重大风险全部双方会签 |
| L4 联动 | 扫描结果驱动服务计划修订与重保立项；合规证据链随手可取，审计零突击 |
| L5 成气候 | 客户方的风险管理节奏受你影响而建立；你的登记册与扫描方法被跨客户复用 |

## 9.7 训练方法

1. **建一册**：为最大的客户建立或重修风险登记册，跑一个月"月度过册"——建册过程就是把脑子里的担心变成体系的过程；
2. **扫一月**：每周快扫坚持一个月，记录每条扫描线的产出率——产出率为零的线要么方法错了，要么你在假装扫；
3. **红队练习**：请一位不熟的同事以攻击者视角审你的客户环境，专挑你"以为没问题"的地方——自己的盲区自己扫不出来；
4. **审计演练**：模拟一次监管问询：随机抽三个上月发生的事件，要求 30 分钟内给出完整证据链（时间线、处置记录、复盘结论）。给不出的地方就是留痕的洞；
5. **AI 杠杆**：把通告聚合、异常初筛、扫描报告初稿交给 AI；但定级、会签、监管口径，人来。AI 时代数据边界的专项训练见第 22、24 章。

## 9.8 三个常见误区

1. **登记册变免责簿**：把风险写下来抄送客户，出事时说"我早写过"。登记册的目的是消灭风险，不是划分责任——写了三年没关过一条风险的册子，是风险管理失败的证据，不是尽职的证据；
2. **合规是合规部门的事**：等合规部门发现，通常已经是监管发现之后。第一公里没人守，后面每一公里都是补救；
3. **只扫技术不扫组织**：系统指标全绿，客户换了个对你们有成见的运维总监，续约季照样翻车。组织风险不进册，等于只防了一半的事故。

## 9.9 自检清单

- [ ] 每个负责客户有风险登记册，本月过册一次
- [ ] 每条风险有具名 Owner、缓解动作、复审日期
- [ ] 重大风险（高概率或高影响）全部双方会签
- [ ] 三道扫描线（技术/业务/组织）各有节奏，本月有新风险入册
- [ ] 客户业务日历上的高危窗口，冻结与值守安排已就绪
- [ ] 任意抽一个近期事件，30 分钟内能给出完整证据链
- [ ] 我用的 AI 工具清单与客户数据分级对照过，无违规输入
- [ ] 对外输出的案例/复盘材料按清单验证过脱敏

**本章要点回顾**

1. 风险是概率题、合规是判断题：前者可权衡，后者没商量；混管的代价两个方向都很贵。
2. 风险登记册是唯一事实源：Owner、动作、复审日期三要素，重大风险双方会签，月度过册。
3. 主动扫描三条线：技术、业务日历、组织异动；节奏是周快扫、月深扫、季体检。
4. 审计监管三纪律：如实、留痕在平时、口径一致；证据链是日常治理的副产品。
5. 数据安全三铁律：不出授权边界、进 AI 先问、脱敏可验证；隐瞒比违反更严重。
