# 附录 H　TAM 工具与平台验收标准（拟定稿）

> 性质说明：本文件是本书发起的**行业标准拟定稿（v0.1，2026-10 拟稿）**，不是任何官方机构发布的标准。它把第 8 章（服务治理）、第 21–23 章（AI 变革篇）与第 26 章（度量体系）中涉及工具与平台的要求收敛为一份可操作的验收框架，供服务组织在选型、上线、续用 TAM 工作平台时对照执行，也作为开源共建的底稿——修订请走附录 E 的贡献流程。文中阈值均为建议值，落地时必须结合本组织业务与监管要求校准；涉及时效性要求处均已标注时点。

## H.0 引言

工具是 TAM 的生产系统。TAM 的判断力再强，数据从错误的 CMDB 里取出来、告警淹没在噪音里、工单记录导不出来，服务质量就没有底座。行业里常见三种失效：重功能轻数据（平台演示漂亮，数据质量无人验收）、重上线轻运营（上线即烂尾，半年后字段全是空的）、重采购轻安全（AI 工具把客户数据传出境无人察觉）。三种失效的共同根源是：没有一份在上线前必须通过的验收标准。

本标准的目的有三：

1. 给选型一把尺：功能、数据、安全、可退出四个维度一次验清；
2. 给上线一道闸：验收不通过不得承载真实客户业务；
3. 给运营一个锚：年度复验，防止平台带病运行、数据腐烂。

## H.1 范围

本标准规定了 TAM 工作所用工具与平台的分类、功能要求、非功能要求、验收流程与判定规则。覆盖六类平台：监控与告警、工单与服务管理、配置与资产（CMDB）、知识库与 RAG、客户健康度与度量、自动化与 AI 工具链。

本标准适用于服务组织自建或采购的 TAM 工作平台的选型验收、上线验收与年度复验。

本标准不适用于：客户生产系统本身的验收（属客户侧项目验收范畴）；通用办公协同工具（IM、邮件、文档）的验收。金融客户的监管专项要求（等保 2.0、数据分级分类）与本标准叠加执行，见第 16 章。

## H.3 术语和定义

下列术语和定义适用于本标准。完整术语表见附录 A。

**验收**：在工具平台承担真实业务前，按本标准逐项核查并给出书面结论的过程。

**数据可信**：平台中数据满足准确、完整、及时三个属性，可支撑度量与评估（第 26 章口径）。

**最小必要权限**：工具账号权限按岗位必需授予，默认只读，写入与导出权限单独审批。

**可退出**：平台的业务数据能以开放格式完整导出，更换平台时不发生数据与历史的实质性丢失。

## H.4 验收原则

**T1 数据可信优先**：功能少可以补，数据假全盘输。验收先验数据链路，再验功能清单。

**T2 最小集成闭环**：监控、工单、CMDB、知识库四者之间必须打通最小闭环（告警生成工单、工单关联配置项、事件沉淀知识），不接受几个孤立系统靠人肉搬运。

**T3 安全合规前置**：权限模型、审计日志、数据边界在上线前验收，不是上线后补。

**T4 AI 可解释与可控**：AI 功能（摘要、聚类、推荐、生成）必须有来源可溯、人工可纠错的机制；涉客户数据的 AI 调用必须走审批过的通道（第 22、24 章）。

**T5 可退出**：验收时实测数据导出，不接受厂商口头承诺。

## H.5 分类与功能验收要求

每项标注【必须】或【建议】。【必须】项是验收的否决性条件。

### H.5.1 监控与告警平台

| 编号 | 要求 | 级别 |
| --- | --- | --- |
| H5.1-1 | 核心链路监控覆盖率可度量：能按系统列出"已覆盖/未覆盖"清单 | 必须 |
| H5.1-2 | 告警分级（至少四级）与值班路由绑定，P1/P2 告警可达值班人（电话/IM 双通道） | 必须 |
| H5.1-3 | 告警降噪能力：抑制、聚合、维护窗口静默；降噪规则可审计 | 必须 |
| H5.1-4 | 告警与工单自动关联：P1/P2 告警自动生成或挂接工单 | 建议 |
| H5.1-5 | 异常检测/AIOps 能力：误报率可度量，接入边界符合第 23 章 | 建议 |

### H.5.2 工单与服务管理平台

| 编号 | 要求 | 级别 |
| --- | --- | --- |
| H5.2-1 | 工单全生命周期留痕：创建、流转、升级、关闭各节点时间戳不可篡改 | 必须 |
| H5.2-2 | 支持 SLA 计时与超时预警，计时口径可配置（响应/解决分开） | 必须 |
| H5.2-3 | 工单数据可完整导出（含附件与历史记录），导出格式开放 | 必须 |
| H5.2-4 | 支持升级矩阵配置（模板 06），升级动作留痕 | 必须 |
| H5.2-5 | 工单智能摘要与聚类（AI），输出附原始工单链接可溯 | 建议 |

### H.5.3 配置与资产（CMDB）

| 编号 | 要求 | 级别 |
| --- | --- | --- |
| H5.3-1 | 配置项与监控对象、工单可关联，三者使用同一套标识 | 必须 |
| H5.3-2 | 有数据保鲜机制：自动发现或对账，超过约定周期未刷新的配置项被标记 | 必须 |
| H5.3-3 | 关键属性（负责人、等级、依赖关系）完整率可度量 | 必须 |
| H5.3-4 | 变更与发布记录可回链到配置项 | 建议 |

### H.5.4 知识库与 RAG

| 编号 | 要求 | 级别 |
| --- | --- | --- |
| H5.4-1 | 知识条目带责任人、失效时间与来源，过期条目自动降权或标记 | 必须 |
| H5.4-2 | 事件复盘（RCA）与知识沉淀打通：RCA 产出可一键转知识条目 | 必须 |
| H5.4-3 | RAG 问答引用来源可见，无来源的回答被明确标识 | 必须 |
| H5.4-4 | 客户数据进入知识库前经脱敏与分级检查（第 9、24 章） | 必须 |
| H5.4-5 | 支持按客户/项目隔离知识空间，权限最小必要 | 建议 |

### H.5.5 客户健康度与度量平台

| 编号 | 要求 | 级别 |
| --- | --- | --- |
| H5.5-1 | 健康分计算口径可配置、可解释，每个分项可下钻到原始数据 | 必须 |
| H5.5-2 | 度量数据来源可审计，满足附录 G 的证据要求 | 必须 |
| H5.5-3 | 指标趋势保留至少 24 个月，支持同比/环比 | 建议 |
| H5.5-4 | 低分预警自动推送责任 TAM 与主管 | 建议 |

### H.5.6 自动化与 AI 工具链（TAM Copilot 类）

| 编号 | 要求 | 级别 |
| --- | --- | --- |
| H5.6-1 | AI 调用客户数据走审批通道，调用日志完整可审计 | 必须 |
| H5.6-2 | AI 产出（纪要、摘要、报告初稿）有"人工确认后发出"的强制环节 | 必须 |
| H5.6-3 | 自动化动作（巡检、采集、通告）有开关与回退，失败可告警 | 必须 |
| H5.6-4 | 模型与提示词版本可管理，变更有记录（第 24 章模型风险） | 建议 |

## H.6 非功能验收要求

| 维度 | 【必须】要求 |
| --- | --- |
| 安全 | 权限最小必要；操作审计日志保留 ≥ 180 天；涉金融客户时满足数据分级分类与本地化要求（第 16 章） |
| 可用性 | 工单与告警平台自身可用性不低于所服务客户的最高 SLA 承诺；平台自身故障时有降级手工流程 |
| 性能 | 核心操作（开单、检索、告警推送）满足约定时延；告警从产生到触达值班人 ≤ 60 秒 |
| 备份与导出 | 全量数据每日备份；业务数据开放格式导出经实测通过 |
| 可观测 | 平台自身纳入监控，平台故障不可"静默失明" |

## H.7 验收流程与判定

验收分三个阶段，每阶段出具书面结论：

1. **选型验证（POC）**：用本组织真实场景样本（至少含一次模拟 P1 事件全流程）验证 H.5 各类【必须】项；
2. **试点验收**：选 1–2 个客户/项目试点运行 ≥ 30 天，验证 H.6 非功能项与数据可信（抽查数据准确率 ≥ 99%）；
3. **上线验收**：全量切换前核查最小集成闭环（T2）与安全项（T3），签署上线结论；上线后 90 天内做一次回头看。

判定规则：

- 【必须】项 100% 通过、【建议】项通过率 ≥ 80% 且未通过项有补救计划，判定为"通过"；
- 年度复验按同一标准执行，重点查数据腐烂（H5.3-2 保鲜率、H5.4-1 过期条目占比）。

否决条款（任一即不通过）：

1. 客户数据未经审批出境或进入未授权的外部 AI 服务；
2. 权限与审计不可查（谁看过、谁改过说不清）；
3. 核心业务数据无法完整导出（实测失败）；
4. 告警到值班人的链路存在单点且无备用通道。

## 本章要点回顾

- 本附录是**开源共建的验收标准拟定稿**，不是官方标准，阈值落地必须校准；
- 五条原则：数据可信优先、最小集成闭环、安全合规前置、AI 可解释可控、可退出；
- 六类平台各有【必须】/【建议】项，【必须】项 100% 通过才判通过，每年复验防数据腐烂；
- 验收三阶段：POC → 试点 ≥ 30 天 → 上线验收，上线 90 天内回头看；
- 四条否决：数据出境违规、权限审计不可查、数据导不出、告警链路单点。
